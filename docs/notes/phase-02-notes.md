## Confirmed MEDI facts (package 10.10/10.11 preview; Learn page + the source it links)
- `IngestionPipeline<T>(IngestionDocumentReader, IngestionChunker<T>, IngestionChunkWriter<T>, IngestionPipelineOptions?, ILoggerFactory?)`; `ChunkProcessors` and `DocumentProcessors` are get-only `IList`s (add, don't assign); `ProcessAsync(IEnumerable<FileInfo>, ct)` / `(DirectoryInfo, pattern, option, ct)` yield `IngestionResult { DocumentId, Document, Exception, Succeeded }`. It processes files sequentially, **one `WriteAsync` per document**, and chunk processors get one `IAsyncEnumerable` per document.
- `Dispose()` on the pipeline **disposes the writer** (and the writer disposes the `VectorStore`). So `IngestionService` builds one writer per pipeline instead of a singleton.
- The identifier passed to the reader is `FileInfo.FullName` (non-virtual `ReadAsync(FileInfo, ct)` calls the virtual file overload, which opens a stream and calls the abstract `ReadAsync(Stream, identifier, mediaType, ct)`). `IngestionResult.DocumentId` is `document.Identifier` (or the path when reading failed).
- `IngestionChunk<string>(content, document, context)` throws on empty/whitespace content; `Metadata` is a lazily created `IDictionary<string, object>`.
- `HeaderChunker(IngestionChunkerOptions)`: the chunk **content starts with the context** (joined heading markdown, e.g. `# Part I ## Item 1A. Risk Factors`), and `Context` holds the same string. `ElementsChunker` never reads `OverlapTokens`, so **overlap is not honored**; the option was removed. A context of >= `MaxTokensPerChunk` tokens throws. Long paragraphs are cut at token boundaries, sometimes mid-word-group.
- `VectorStoreWriter<string>(VectorStore, int, VectorStoreWriterOptions)`; `DistanceFunction` / `IndexKind` options are strings (`DistanceFunction.CosineSimilarity`, `IndexKind.Hnsw`); with `string` vector properties the store's `EmbeddingGenerator` embeds `chunk.Content` (document-prefix generator via `AddSecFilingsVectorStore(DocumentEmbeddingKey)`).
- `MarkdownReader.ReadAsync(Stream, id, "text/markdown")` builds headers, paragraphs and tables.
- `FunctionsApplication.CreateBuilder` loads `appsettings.json` itself (Learn); confirmed because bumping `Indexing:Cleaning:Version` in that file changed the fingerprint and triggered a re-index.
- The chunker renders tables with `Environment.NewLine`, so chunk text has `\r\n`; cleaning normalizes to `\n`.

## For Phase 03
- Table: `sec_filing_chunks`; collection `VectorStoreCollection<Guid, FilingChunkRecord>` (the record already maps `indexfingerprint`). Column names are listed above. The vector extension is enabled when `AddSecFilingsVectorStore` first resolves the store, so no separate setup is needed before searching.
- Chunk `content` is the cleaned text, already free of table pipes and running footers; `section` is the last heading of the chunk's context (`Item 1A. Risk Factors`); `containsinstructionliketext` is `false` for all 5 filings.
- Keys are random per index run: cite `documentid` + `section`, never `key`.
- The table is created by `VectorStoreWriter` on the first write; before the first index run `CollectionExistsAsync()` is false, so search must return empty results instead of failing.

## Commands & operating notes
- **Run** (PowerShell 7.3+): `aspire start; aspire wait ingestion-init --status down --timeout 3600; aspire wait indexing` once the CLI matches the AppHost (`aspire update`). Until then: `dotnet run --project src\SECFilingsAgenticRag.AppHost --no-build`, then find the Function URL: `Select-String -Path (Get-ChildItem $env:TEMP\aspire-dcp*\*_out | Sort-Object LastWriteTime -Descending) -Pattern 'Index: \[POST\] (http://\S+)/api/index'` (use the newest `aspire-dcp*` folder).
- **Index (nothing indexes automatically):** `./scripts/Invoke-Indexing.ps1` (add `-BaseUrl http://localhost:<port>` while `aspire describe` is unusable; `-Tickers AAPL,MSFT`; `-Force`). Exit codes: 0 ok, 1 a document failed, 2 Function unreachable, 3 another run is active (409), 4 no report received (the proxy cut a long run; watch the log, then re-run: finished filings show `skipped`). For a cold full index, index per ticker (`-Tickers AAPL`, ...) to stay under the proxy cutoff and get every report.
- **Commands:** `aspire resource indexing reindex` / `reindex-force`, or the dashboard buttons (not exercised here, see deviation 14).
- **Direct HTTP:** `Invoke-RestMethod -Method Post -Uri "$url/api/index" -ContentType 'application/json' -Body '{"tickers":["AAPL"],"force":false}'` returns `{"startedAt":…,"documents":[{"documentId":…,"status":"skipped"|"indexed"|"failed",…}],"indexed":0,"skipped":1,"failed":0}`.
- **Re-index rules:** a filing is skipped when all its chunks carry the current `indexfingerprint` and their count equals `chunkcount`. The fingerprint hashes the blob's `contentsha256` and the whole `Indexing` configuration section except `StagingPath`. Changing `MaxTokensPerChunk` or any `Indexing:Cleaning:*` value re-indexes affected filings on the next normal run. **When cleaning/reader code changes, bump `Indexing:Cleaning:Version`** in the Function's `appsettings.json`. `-Force` is only for rebuilding unchanged filings. A different embedding model needs a code change (constants) and a table change; drop the table (below).
- **psql** (the container name starts with `postgres`; stdin form avoids quoting problems):
  ```powershell
  $pg = docker ps --filter "name=postgres" --format "{{.Names}}" | Select-Object -First 1
  'SELECT ticker, fiscalyear, COUNT(*) FROM sec_filing_chunks GROUP BY 1,2 ORDER BY 1;' | docker exec -i $pg sh -c 'PGPASSWORD="$POSTGRES_PASSWORD" psql -U postgres -d secfilings'
  ```
  Useful queries: `\d+ sec_filing_chunks`; `SELECT DISTINCT documentid, chunkcount FROM sec_filing_chunks ORDER BY 1;`; `SELECT COUNT(*) FILTER (WHERE content LIKE '%|%') pipes, COUNT(*) FILTER (WHERE containsinstructionliketext) flagged, COUNT(DISTINCT indexfingerprint) FROM sec_filing_chunks;`; reset: `DROP TABLE sec_filing_chunks;`.
- **Logs:** per document `Cleaned <id> boilerplateLines=… flagged=… excluded=…` and `Indexed <id> chunks=… in …` (failed documents log `Failed <id> chunks=0 …`; skipped ones are only in the report).
- **Standalone `func start`:** copy `local.settings.sample.json` to `local.settings.json` (git-ignored) and fill in the connection strings. Under Aspire, the AppHost's environment variables override both JSON files.
- **Gotchas:** (1) the Functions host proxy drops long synchronous requests (deviation 18); (2) MEDI's pipeline disposes its writer and store; (3) the chunker puts the heading path into the chunk text and uses CRLF; (4) after the laptop sleeps, Npgsql calls in a running indexing request time out ("The operation has timed out"); restart the AppHost and re-run; (5) do not `dotnet build` while the AppHost runs (the Functions DLLs are locked); (6) the bash tool breaks on apostrophes in heredocs, use the file tools.

## Design notes worth knowing
- **Why `HeaderChunker`:** 10-K "Item N." headings are the semantic boundaries and give section citations; `SemanticSimilarityChunker` needs an embedding call per sentence, `DocumentTokenChunker` ignores structure, `SectionChunker` splits on pages. No measured comparison was run.
- **Why two custom processors:** MEDI's built-in chunk processors are LLM enrichers (summary, keywords, classification, sentiment); none cleans text or stamps known metadata. `HtmlFilingReader` exists because `MarkdownReader` / `MarkItDownReader` do not strip inline XBRL, flatten layout tables or promote bold `Item` lines to headings.
- **Considered and NOT applied** (RAG guide: "test first"): stop-word removal ("not" carries meaning), spelling correction (tickers, product names, GAAP terms), number-to-words and abbreviation expansion (figures, "MD&A"), localization (English only), lowercasing (needs the Phase 06 evaluation; there is no normalization layer on disk).
- **Prompt-injection flagging** is a heuristic and never logs matched text; modes `Flag` (default) and `Exclude`.
- **Crash semantics:** an embedding or upsert failure leaves the previous version intact because the writer deletes old keys only after all new chunks are written; a crash mid-upsert leaves old plus partial chunks, which the count check reports as not up to date, and the next run replaces them all.
